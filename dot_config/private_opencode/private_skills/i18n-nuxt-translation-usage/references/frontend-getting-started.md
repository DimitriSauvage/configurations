# Getting started

## Prerequisites

- Nuxt `>=4.0.0`
- Node `>=20.19.0`

## Installation

Install the module and its peer dependencies:

```bash
npm install @beetween/nuxt-translation i18next i18next-browser-languagedetector i18next-http-backend i18next-mf2 i18next-vue
```

## Register the module

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['@beetween/nuxt-translation'],
});
```

No further configuration is required if your project uses the default folder layout.

## Add translation files

Create a `public/locales/` directory with one subdirectory per language. Add one or more JSON files per language — split by feature or domain as you see fit:

```
public/
└── locales/
    ├── fr/
    │   ├── common.json
    │   ├── auth.json
    │   └── my-feature.json
    └── en/
        ├── common.json
        ├── auth.json
        └── my-feature.json
```

At dev server start and at each production build, the module merges all `.json` files in each language directory into a single `translations.json` using a **deep merge** (`lodash-es` `merge()`).

**Example:**

```json
// fr/common.json
{ "actions": { "save": "Enregistrer", "cancel": "Annuler" } }

// fr/my-feature.json
{ "actions": { "delete": "Supprimer" }, "feature": { "title": "Ma fonctionnalité" } }
```

Results in:

```json
// fr/translations.json  ← generated
{
  "actions": {
    "save": "Enregistrer",
    "cancel": "Annuler",
    "delete": "Supprimer"
  },
  "feature": {
    "title": "Ma fonctionnalité"
  }
}
```

> **Do not edit `translations.json` manually** — it is regenerated on every build and dev server start.

### Gitignore

Add `translations.json` to your `.gitignore` so generated files are not committed:

```gitignore
# Generated by @beetween/nuxt-translation
public/locales/**/translations.json
```

### Conflict resolution

When two files define the same key, the **last file read wins**. Files are processed in filesystem order (typically alphabetical). To control merge priority, prefix file names (e.g., `01-base.json`, `02-override.json`).

## Use translations in components

`useTranslation` is auto-imported module-wide, no import statement needed:

```vue
<script setup lang="ts">
const { t } = useTranslation();
</script>

<template>
  <h1>{{ t('common.title') }}</h1>
</template>
```

## Translation syntax (MF2)

Translation strings use the [Message Format 2 (MF2)](https://unicode-org.github.io/icu/userguide/format_parse/messages/) syntax. Variables are written as `{$varName}` (not `{{varName}}`).

### Variables

```json
{ "greeting": "Hello, {$name}!" }
```

```ts
t('greeting', { name: 'Alice' }) // → "Hello, Alice!"
```

### Plurals

```json
{ "items": "{$count, plural, one {# item} other {# items}}" }
```

```ts
t('items', { count: 1 }) // → "1 item"
t('items', { count: 5 }) // → "5 items"
```

### Dates

```json
{
  "created": "Created on {$date, :date style=long}",
  "time":    "At {$date, :time style=short}"
}
```

```ts
t('created', { date: new Date('2024-06-15') }) // → "Created on June 15, 2024"
```

> MF2 draft functions (`:date`, `:time`, `:datetime`, `:number`, `:currency`, `:unit`, `:math`) are enabled by default.

## Language detection

The module uses `i18next-browser-languagedetector` to pick the active language from the browser. Language codes are automatically **normalised to their base form**: `fr-FR` and `fr-BE` both resolve to `fr`. Detection results are **not cached** (no `localStorage` or cookie written), so the browser language is re-evaluated on every page load.
